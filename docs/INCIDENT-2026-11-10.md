- Snapshot `data/status.json` as of 2026-11-09T16:00:03Z: 488 stored, 469 stale, **0 publishable**; Awin offers and programme discovery return HTTP 401, while direct and Impact source collection report OK.
- Current product data cannot safely support live product pages. Existing links/programme entries without complete product data are not silently promoted into verified offers.

## Root causes

1. The Awin API replies HTTP 401 for both publisher promotions and joined programmes. A valid authorized `AWIN_API_TOKEN` / matching `AWIN_PUBLISHER_ID` is required. This cannot be fixed by inventing tokens or relaxing product eligibility.
2. The stale inventory and the absence of verified complete offers explain the empty build and data-dependent tests. Tests that expect product detail pages are correctly failing in this state.
3. The update workflow previously executed the full data-dependent test suite **before** attempting a source refresh. A stale snapshot could therefore prevent the source updater from ever running.
4. Diagnostics and artifact retention were insufficient on failed jobs. Concurrent schedule/push runs could queue unnecessary updates.

## Changes made

- Update workflow: perform structural checks, refresh actual sources, print sanitized source health, enforce a nonempty verified product catalogue, then execute the complete test suite and the existing build/validation/security gates. Failed updates keep an artifact with the existing status and reports.
- Added `scripts/catalog-health.mjs` / `npm run catalog:health` as a fast, honest failure when the verified product inventory is empty. It does **not** turn a genuine outage green.
- Integrity workflow: show source health and fail fast on empty catalogue; save status diagnostics. Repeated dispatches are protected against overlapping runs.
- Quality workflow: log source state before full tests; keep `data/status.json` with its existing quality artifacts.
- Update workflow concurrency: cancel obsolete overlapping runs. Scheduled refresh cadence is unchanged; existing site files, brand design, source adapters, and release gates remain intact.

## Follow-up needed

1. In GitHub repository **Settings → Secrets and variables → Actions**, verify that `AWIN_PUBLISHER_ID` identifies the correct authorized publisher and refresh **`AWIN_API_TOKEN`** using the publisher's official Awin API access. Never paste credentials into issues, logs, or Git commits.
2. Re-run `Angebote aktualisieren` manually. Success requires **at least one complete, current, approved product** and passing `npm test`, `npm run check`, `npm run build`, `npm run validate`, `npm run seo`, and `npm run security`.
3. After a successful deployment, verify `data/status.json`, generated offer detail pages, website product links, scheduled update jobs, and the live site. Check 401 errors and nonzero publishable products.
4. Source availability and credentials require separate verification. Avoid falsely describing the catalogue as current while the source remains unauthorized.

No paid services, new trial plans, secrets, or fabricated offers are introduced.
